# 데이터 수집·검증 규칙

`theaters.json`을 만들거나 갱신할 때 반드시 아래 절차를 따른다.
이 문서는 2026-08 초기 데이터 구축 때 **CGV 김포 SCREENX관이 누락된 사고**의 재발 방지를 위해 작성됐다.

## 사고 기록 (2026-08-10)

- 증상: 운영 중인 CGV 김포 SCREENX관(공식 "이달의 SCREENX" 선정 지점)이 데이터에 없었음.
- 원인:
  1. 지점 **목록의 1차 소스여야 할 CGV 공식 특별관 페이지**(`cgv.co.kr/cnm/specialCnm/detail?sscnsNo=4`)가
     수집 환경의 네트워크 정책으로 접근 불가였음 (나무위키 원문도 동일).
  2. 그래서 목록을 **검색 결과 요약·기사 같은 2차 소스**로 구성했는데, 이런 소스는
     용산·영등포처럼 화제가 된 지점 위주라 김포 같은 조용한 지점이 빠지는 편향이 있음.
  3. 수집된 지점 수를 **공식 목록의 지점 수와 대조하는 검증 단계가 없어서** 누락이 그대로 통과됨.
- 상태: 김포 외 다른 지점도 같은 이유로 빠져 있을 수 있음. **공식 목록과 전수 대조 전까지
  ScreenX 목록은 불완전한 것으로 간주할 것.**

## 전수 대조 결과 (2026-08-10)

cgv.co.kr·namu.wiki가 데이터센터 IP를 차단(Cloudflare)해 공식 페이지 직접 대조는 불가.
대신 특별관 전문 커뮤니티 DB(muko.kr)의 포맷별 보유관 목록을 기준선으로 삼고,
차이가 나는 지점 전부를 뉴스·공식 이벤트 페이지로 개별 검증했다.

- **추가 (11지점)**: ScreenX 5곳(김포·배곧·강릉·안산·오리) + 의정부 ScreenX관,
  돌비 6곳(구의이스트폴·목동·상암월드컵경기장·청주터미널·수원스타필드·고양스타필드).
  김포·배곧·인천·의정부 ScreenX는 2026년 5월 신규/리뉴얼이라 커뮤니티 DB에도 없었음.
- **메가박스 DVA관 주의**: 2025년 이후 신규 돌비관은 공식 'Dolby Cinema' 브랜드가 아닌
  자체 'DVA(Dolby Vision + Atmos)'관. 본 데이터는 DolbyCinema 포맷으로 분류하되 notes에 구분.
- **muko.kr 과분류 제외 (5곳)**: 포항·대전현대프리미엄아울렛·원주혁신·전주혁신·충주연수는
  Dolby Atmos(사운드)관만 있어 돌비 시네마 아님 — 커뮤니티 DB도 오류가 있으니 개별 검증 필수.
- **위치 교정**: CGV 대구의 IMAX는 한일극장(동성로)이 아니라 침산로 93 이마트 칠성점
  (구 메가박스 대구, 2022년 재개관). 동성로의 'CGV 대구한일'은 IMAX 없는 별개 지점.
- **미포함 (오픈 예정)**: CGV 여의도 3면 LED SCREENX(세계 최초, 2026년 하반기 예정) —
  오픈 확인 후 추가할 것.
- ULTRA 4DX(4DX+SCREENX 결합)관은 muko.kr에서 4DX로 분류되므로 ScreenX 대조 시 주의.

## 좌표 재검증 (2026-08-10) — 사고 기록 2

- 증상: 마커 위치가 실제 극장과 수백 m~수 km 어긋난 지점 다수 (사용자 제보).
- 원인: 초기 구축 당시 지오코딩 API가 전부 차단된 환경이라 좌표를 지식 기반
  추정값으로 입력했고, 좌표를 검증하는 절차가 없었음.
- 조치 (현행 방법론):
  1. Nominatim으로 **극장 이름 POI 검색 + 도로명 주소 지오코딩** 두 갈래 수행
  2. 두 결과가 500m 이내로 일치할 때만 자동 신뢰, 나머지는 전부 플래그
     (축약 이름 검색은 동명 타지역 지점·폐점 지점에 오매칭되는 함정이 많음)
  3. 지점별 검증 에이전트가 입점 건물·인근 랜드마크·OSM 건물 폴리곤으로 후보를 심판
  4. `scripts/validate.py`가 주소의 시/도와 좌표의 바운딩 박스 일치를 기계 검증
- 결과: 55개 전 지점 재판정. 좌표 출처는 `geoSrc`(osm_poi/addr_geocode/corrected 등),
  확신도는 `geoConf`로 기록. 이 과정에서 **주소 자체가 틀린 지점 2곳**도 발견·교정:
  - CGV 천호: 천호대로 1005(오류) → 양재대로 1571 홈플러스 강동점 (굽은다리역)
  - CGV 동탄: 롯데백화점 동탄점(오류 — 그곳은 롯데시네마) → 메타폴리스 타임테라스
- 교훈: 좌표·주소도 지점 목록과 동일하게 **출처와 검증 절차 없이는 신뢰하지 않는다.**
  새 지점 추가 시 Nominatim POI/주소 이중 확인 후 `geoSrc`를 반드시 기록할 것.
- 추가 함정 (등촌 사례, 2026-08-10): 자유형(q=) 주소 지오코딩은 번지를 옆 골목으로
  잘못 보간해도 표시 주소는 질의한 도로명을 그대로 돌려줘 그럴듯해 보인다.
  반드시 **역지오코딩으로 실제 도로명을 재확인**하고, 가능하면 structured 검색
  (street 파라미터)으로 건물 매칭을 받을 것. (등촌: 45길 질의 → 49길 지점 반환,
  340m 오차. structured 검색은 '더브리티시몰' 건물을 정확히 매칭함)

## 전수 좌표 감사 (2026-08-10) — 사고 기록 3

- 계기: 등촌 수정 후에도 김포가 틀려 있다는 사용자 제보. "왜 자꾸 틀리는가"에 대한 답:
  1. **원죄**: 초기 좌표가 전부 무검증 추정값이라, 이후 모든 작업이 오류를 '걷어내는'
     작업이 됨. 걷어내는 검증 자체에 구멍이 있으면 그만큼 오류가 살아남는다.
  2. **검증 도구의 함정이 층층이 존재**: 지오코더 번지 보간 오류, 표시 주소 에코,
     동명 타지역 지점 매칭, OSM의 중복·오배치 노드(같은 극장 노드가 2개 있거나
     엉뚱한 위치에 찍혀 있음 — 신촌·소풍·인천·판교·세종·압구정에서 확인).
  3. **검사 코드 버그**: 도로명 대조를 부분 일치로 해서 '풍무로'가 '풍무로57번길'에
     매칭돼 김포 오류가 통과됨. → 완전 일치로 수정.
- 조치: `scripts/geo-audit.py`로 55개 전 지점을 3중 증거(주변 cinema POI,
  structured 건물 매칭, 역지오코딩 도로명 완전 일치)로 전수 감사.
  40곳 정상, 15곳 플래그 → 개별 판정 후 7곳 교정(김포·압구정·소풍·인천·판교·세종 +
  등촌은 직전 라운드), 나머지는 인근 타 극장 POI가 잡힌 오탐으로 판정.
- 부수 발견: **CGV 판교의 입점 건물은 알파돔타워가 아니라 현대백화점 판교점**
  (판교역로146번길 20). 주소·노트 교정.
- 원칙: 좌표 갱신 시 반드시 `scripts/geo-audit.py`를 돌려 리포트가 깨끗한지 확인하고,
  단일 소스(특히 이름 검색 POI 1건)만으로 좌표를 확정하지 않는다 —
  **서로 독립인 증거 2개 이상이 일치할 때만 신뢰**한다.

## 좌석 시뮬레이션 데이터 (`data/halls.json`, 2026-08-10)

- IMAX·돌비 33개관의 열 수·열 문자·열당 좌석·명당 통설·구조 특이사항을
  나무위키 지점 문서와 커뮤니티(익스트림무비·클리앙·디시·무코 등)에서 수집.
  각 항목에 sources URL 기록. 확인 안 된 항목은 생략 → 시뮬레이터가
  스크린 크기 기반 파라메트릭 기본값으로 대체.
- 확보 현황: 열 수 12개관, 명당 열 26개관. 첫 열 거리·단차 실측은 전무 —
  시뮬레이터의 해당 값은 극장 설계 표준 근사이며 UI에 추정임을 명시.
- 갱신 방법: 실제 좌석배치도(예매 페이지)를 확인하면 halls.json의 해당 관에
  rows / rowLetters / maxSeatsPerRow / seats를 채운다. 리뉴얼(리클라이너 전환)로
  열·좌석 수가 자주 바뀌므로 sources에 확인 날짜가 있는 출처를 남길 것.

## 수집 규칙

1. **지점 "목록"은 공식 페이지가 유일한 1차 소스다.**
   - IMAX: https://cgv.co.kr/cnm/specialCnm/detail?sscnsNo=1
   - SCREENX: https://cgv.co.kr/cnm/specialCnm/detail?sscnsNo=4
   - Dolby Cinema: https://www.megabox.co.kr (특별관 안내)
   - 공식 페이지에 접근할 수 없는 환경이라면, 목록을 확정하지 말고
     "공식 목록 미대조" 상태임을 PR·커밋 메시지에 명시한다.
2. **2차 소스(나무위키, 기사, 커뮤니티)는 스펙 보강용으로만 쓴다.**
   스크린 크기·좌석 수·리뉴얼 이력은 2차 소스로 채우되, 지점의 존재 여부를
   2차 소스만으로 판단하지 않는다.
3. **개관·폐관 반영**: 폐관은 공식 공지 또는 복수 출처 확인 후에만 제거한다.

## 갱신 시 검증 체크리스트

- [ ] 공식 페이지의 포맷별 지점 수 == `theaters.json`의 포맷별 지점 수
- [ ] 공식 페이지 지점명을 하나씩 데이터와 대조 (수가 같아도 구성이 다를 수 있음)
- [ ] `python3 scripts/validate.py` 통과 (스키마·중복 ID·좌표 범위·포맷별 카운트 출력)
- [ ] 폐관 예정 지점은 삭제하지 말고 `notes`에 폐점 예정일 명시
