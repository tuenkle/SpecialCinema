# 데이터 수집·검증 규칙

`theaters.json`을 만들거나 갱신할 때 반드시 아래 절차를 따른다.
이 문서는 2026-08 초기 데이터 구축 때 **CGV 김포 SCREENX관이 누락된 사고**의 재발 방지를 위해 작성됐다.

## 사고 기록 (2026-08-10)

- 증상: 운영 중인 CGV 김포 SCREENX관(공식 "이달의 SCREENX" 선정 지점)이 데이터에 없었음.
- 원인:
  1. 지점 **목록의 1차 소스여야 할 CGV 공식 특별관 페이지**(`cgv.co.kr/cnm/specialCnm/detail?sscnsNo=4`)가
     수집 환경의 네트워크 정책으로 접근 불가였음 (나무위키 원문도 동일).
  2. 그래서 목록을 **검색 결과 요약·기사 같은 2차 소스**로 구성했는데, 이런 소스는
     용산·영등포처럼 화제가 된 지점 위주라 김포 같은 조용한 지점이 빠지는 편향이 있음.
  3. 수집된 지점 수를 **공식 목록의 지점 수와 대조하는 검증 단계가 없어서** 누락이 그대로 통과됨.
- 상태: 김포 외 다른 지점도 같은 이유로 빠져 있을 수 있음. **공식 목록과 전수 대조 전까지
  ScreenX 목록은 불완전한 것으로 간주할 것.**

## 수집 규칙

1. **지점 "목록"은 공식 페이지가 유일한 1차 소스다.**
   - IMAX: https://cgv.co.kr/cnm/specialCnm/detail?sscnsNo=1
   - SCREENX: https://cgv.co.kr/cnm/specialCnm/detail?sscnsNo=4
   - Dolby Cinema: https://www.megabox.co.kr (특별관 안내)
   - 공식 페이지에 접근할 수 없는 환경이라면, 목록을 확정하지 말고
     "공식 목록 미대조" 상태임을 PR·커밋 메시지에 명시한다.
2. **2차 소스(나무위키, 기사, 커뮤니티)는 스펙 보강용으로만 쓴다.**
   스크린 크기·좌석 수·리뉴얼 이력은 2차 소스로 채우되, 지점의 존재 여부를
   2차 소스만으로 판단하지 않는다.
3. **개관·폐관 반영**: 폐관은 공식 공지 또는 복수 출처 확인 후에만 제거한다.

## 갱신 시 검증 체크리스트

- [ ] 공식 페이지의 포맷별 지점 수 == `theaters.json`의 포맷별 지점 수
- [ ] 공식 페이지 지점명을 하나씩 데이터와 대조 (수가 같아도 구성이 다를 수 있음)
- [ ] `python3 scripts/validate.py` 통과 (스키마·중복 ID·좌표 범위·포맷별 카운트 출력)
- [ ] 폐관 예정 지점은 삭제하지 말고 `notes`에 폐점 예정일 명시
